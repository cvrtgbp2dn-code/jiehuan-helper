### 关键网络发现（实测，决定更新方案）

| 地址 | 国内可访问性 |
|---|---|
| `github.com` | ✅ 200（约 6 秒，偏慢） |
| `api.github.com` | ❌ 000 |
| `raw.githubusercontent.com` | ❌ 000 ← **原方案用它读 version.json，会失效！** |
| `cdn.jsdelivr.net` | ✅ **200（0.4~1.1 秒，最稳）** |
| `fastly.jsdelivr.net` | ✅ 301 |
| `gitee.com` | ❌ 000（且 Gitee 要实名+附件限100MB，不适合） |
| GitHub Release 下载（`github.com/.../releases/download/...`） | ✅ 302 重定向到 `release-assets.githubusercontent.com`，跟随重定向后 **200 成功下载** |

**结论与调整**：
- version.json 改用 **jsDelivr 主源** + raw 备用：`https://cdn.jsdelivr.net/gh/OWNER/REPO@main/version.json`
- `_build/main.js` 的更新源改成**多源数组依次尝试**（`feedUrls()` 返回数组，`check-update` 循环直到成功），同时支持 `update-config.json` 用字符串或数组覆盖
- app.asar / 完整包仍走 GitHub Release（已验证可用），地址填 `https://github.com/OWNER/REPO/releases/download/<tag>/app.asar`

## 自动检查更新增强

原实现只在启动后 4 秒静默检查一次——但本软件常驻托盘，开着好几天就再也不会检查。已增强为按需自动检查：

- `autoCheckUpdate(force)` 统一入口，**30 分钟节流**（`lastAutoCheck`），避免频繁联网
- **启动后 4 秒**检查一次（force 跳过节流）
- **每 6 小时**定时检查
- **窗口从托盘唤出**（`visibilitychange` → `!document.hidden`）时检查 ← 最实用
- **窗口重新获得焦点**（`focus`）时检查
- 正在下载/已下载完（`updStep==='downloading'/'ready'`）时跳过，不重复检查
- 新增 `updAutoSeen`：用户点「稍后」后，**本次运行内不再自动弹同一版本**（手动检查仍可见；重启软件会再次提醒）
- 检查失败仍静默忽略，不打扰记账

help.html「软件更新」小节同步补充了「什么时候会自动检查」「稍后不再打扰」「检查失败静默忽略」三条说明。

验证：功能点 8/8 + asar 内容 10/10 通过，zip 85 文件完整性 OK。
